# v2.1 Taxonomy Design (Revised)

Three frozen taxonomies before any conversation authoring.
Versioned as `ontology_v2.1.json`.

---

## 1. Intent Taxonomy (24)

### Principle

Intent = **what the user wants to accomplish**.

Micro-intents that are really knowledge sub-categories get folded into
broader intents — unless they are high-frequency or require different
retrieval sources.

### Top-level intents (24)

| Intent | Description | Knowledge categories |
|---|---|---|
| `admission` | Eligibility, process, how to apply | process, eligibility |
| `cutoff` | Previous year cutoffs, closing ranks | year, branch, category |
| `seats` | Seat count, intake, capacity | branch, total |
| `department` | Branch/department information | available, details |
| `document` | Required documents for admission/counseling | list, format |
| `fee` | Fee structure, payment, installment | tuition, hostel_fee, total |
| `placement` | Job outcomes, recruiters, salary | package, recruiter, record |
| `hostel` | Accommodation, mess, facilities | room, mess, fee, amenities |
| `scholarship` | Financial aid, waivers, concessions | merit, sports, means, post_matric |
| `institution` | College info, contact, faculty, HOD, timings | contact, faculty, hod, timings |
| `safety` | Campus safety, security | campus, girls_safe |
| `transfer` | College transfer, migration | process, eligibility |
| `distance_education` | Online, correspondence, distance programs | university, recognition |
| `management_quota` | Paid seats, donation | policy, process |
| `nri_admission` | International/NRI students | quota, documents |
| `sports_quota` | Athletic admission | certificate, trial |
| `lateral_entry` | Diploma to degree, direct second year | eligibility, process |
| `counseling_info` | Counseling schedule, choice filling | dates, documents |
| `grievance` | Complaints, re-evaluation, issues | process, escalation |
| `career_confusion` | Undecided, dilemma | guidance |
| `loan` | Education loan | eligibility, bank |
| `greeting` | Hello, namaste | — |
| `repeat` | Repeat, say again | — |
| `unknown` | Unclear or out-of-scope | — |

### What changed from v2.0 (28 → 24)

| Removed intent | Merged into | Knowledge category |
|---|---|---|
| `faculty` | `institution` | faculty |
| `hod` | `institution` | hod |
| `contact` | `institution` | contact |
| `timings` | `institution` | timings |
| `recommendation` | `admission` | (general guidance) |

### What was kept separate (per feedback)

- `cutoff` — different retrieval source than admission process
- `department` — department info ≠ admission workflow
- `document` — high-frequency, different retrieval source
- `seats` — distinct from cutoff (capacity vs. qualifying rank)

## 2. Action Taxonomy (15)

### Principle

Action = **what the counselor does**.

Domain-specific information comes from `knowledge_needed` carried through
`provide_program_info`. Narrow actions kept only where the response
structure is fundamentally different.

### Actions (15)

| Action | Description | When used |
|---|---|---|
| `collect_profile` | Ask for rank, PCM, category, interest | Profile incomplete |
| `encourage_and_collect_profile` | Reassure + collect profile | Anxious student, profile incomplete |
| `recommend_branches` | Branch recommendations based on eligibility | Profile complete, brain has data |
| `provide_admission_guidance` | Explain admission process | Admission workflow questions |
| `provide_cutoff_info` | Cutoff data with branch/category breakdown | Cutoff queries |
| `provide_program_info` | Domain-specific information (parameterized) | Any specific info request |
| `provide_fee_info` | Fee structure and payment | Fee queries |
| `provide_placement_info` | Placement statistics and recruiters | Placement queries |
| `provide_hostel_info` | Hostel facilities and fees | Hostel queries |
| `provide_scholarship_info` | Scholarship options and eligibility | Scholarship queries |
| `explain_policy` | Policy explanation (management quota, NRI, transfer) | Policy questions |
| `reassure` | Emotional support, anxiety management | Anxious/emotional student |
| `clarify` | Ask for clarification | Ambiguous/unclear query |
| `provide_guidance` | General personalized guidance | Broad/unclear goals |
| `provide_career_guidance` | Career counseling and path advice | Career confusion |

### What changed from v2.0 (22 → 15)

| Removed action | Mapped to | Knowledge parameter |
|---|---|---|
| `provide_branch_guidance` | `recommend_branches` | — |
| `provide_distance_ed_info` | `provide_program_info` | distance_education_information |
| `provide_nri_admission_info` | `explain_policy` | nri_admission_information |
| `explain_management_quota_policy` | `explain_policy` | management_quota_information |
| `provide_grievance_process` | `provide_program_info` | grievance_information |
| `provide_transfer_info` | `explain_policy` | transfer_information |

### What was kept separate (per feedback)

- `provide_cutoff_info` — cutoff retrieval is measurable and distinct

### Knowledge-to-action routing

```python
# Narrow actions for specific knowledge types
_KNOWLEDGE_TO_ACTION = {
    "fee_information": "provide_fee_info",
    "placement_information": "provide_placement_info",
    "hostel_information": "provide_hostel_info",
    "scholarship_information": "provide_scholarship_info",
    "cutoff_information": "provide_cutoff_info",
}

# Policy-type knowledge routes through explain_policy
_POLICY_KNOWLEDGE = {
    "nri_admission_information",
    "management_quota_information",
    "transfer_information",
}

# Everything else routes through provide_program_info
# with the knowledge_needed parameter carried forward
```

## 3. Behavior Coverage Taxonomy (16 behaviors, 10 operators)

### Principle

Behavior = **what the system must do**, independent of intent names.

This is what the benchmark actually measures. Intent labels are
implementation details that may change.

### Behaviors (16)

| Behavior | Description | Reasoning operators needed |
|---|---|---|
| `greeting` | Acknowledge and initiate | — |
| `information_retrieval` | Answer factual question about college | retrieval |
| `eligibility_check` | Determine if student qualifies | retrieval, eligibility |
| `fee_explanation` | Explain cost structure | retrieval |
| `branch_recommendation` | Suggest branches based on profile | retrieval, eligibility, comparison, recommendation |
| `scholarship_guidance` | Explain aid options and eligibility | retrieval, eligibility |
| `career_counseling` | Help student decide path | comparison, recommendation |
| `emotional_support` | Reassure anxious student | — |
| `correction_handling` | Process student correction to earlier info | correction, memory_use |
| `topic_switch` | Handle mid-conversation topic change | memory_use, follow_up_reference |
| `follow_up_reference` | Answer follow-up using prior context | memory_use, follow_up_reference |
| `policy_explanation` | Explain institutional rules | retrieval, policy_application |
| `ambiguous_query_resolution` | Handle unclear questions | clarification |
| `out_of_scope_handling` | Handle irrelevant or adversarial input | — |
| `multi_constraint_reasoning` | Consider rank + budget + location + interest | comparison, eligibility, multi_constraint |
| `conflict_resolution` | Resolve conflicting student statements | conflict_resolution |

### Reasoning operators (10)

| Operator | Description | Example |
|---|---|---|
| `retrieval` | Look up factual information | "What are the fees?" |
| `comparison` | Compare options against criteria | "CSE vs ECE at 25k rank" |
| `eligibility` | Check if student qualifies | "Can I get CSE with 82%?" |
| `recommendation` | Suggest best option | "Which branch should I pick?" |
| `correction` | Process updated/changed information | "Actually my rank is 28000" |
| `memory_use` | Reference earlier conversation context | "What about the one you mentioned?" |
| `multi_constraint` | Reason across multiple factors | Rank + budget + location + interest |
| `conflict_resolution` | Resolve contradictory statements | "I want CSE but I'm not interested in coding" |
| `follow_up_reference` | Use prior turn's information | "How about for that branch?" |
| `policy_application` | Apply institutional rules to student case | "NRI quota requires these documents" |

### Coverage targets

- Every behavior: ≥2 conversations
- Every reasoning operator: ≥3 conversations
- Multi-constraint reasoning: ≥30% of conversations
- Correction: ≥20% of conversations
- Memory use: ≥40% of conversations
